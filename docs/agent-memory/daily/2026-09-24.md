## Order pipeline diagnosis (later same day)

- Webhooks DO reach shopify-shell and pass HMAC (225 received in the Jul log). Pipeline does not lose orders: Shopify sent only 5 order webhooks ever (2 ORDERS_CREATE + 3 ORDERS_FULFILLED) = the 5 rows in `orders`.
- Compliance 401s are all "invalid Shopify signature" — most likely Shopify's own automated checks, where 401 is the correct answer.
- ROOT CAUSE of duplicate merchants: `.maybeSingle()` on integrations-by-shop with the error ignored. With >=2 rows it returns data=null, and:
  - `routes/shopify.ts` install-sync treats the shop as new -> inserts ANOTHER merchant + integration.
  - `routes/webhooks.ts` /webhooks/commerce/shopify -> 404 "Integration not found for shop" (146 seen) -> orders/uninstall/subscription webhooks dropped.
  - `lib/shopifySession.ts` verifyShopifySessionToken -> "new install".
  - `middleware/auth.ts` internal lookup (no status filter) -> 403 -> shell's "bootstrap repair on 403" calls install-sync -> feedback loop.
  - No unique constraint on (provider, shop) -> first duplicate likely a race between afterAuth and bootstrap.
- Numbers: 83 merchants = 11 shops. 8 shops OK (1 row). Broken: shop A (41 rows, all 2026-08-07), shop B (23, Jun-Jul), Shopify's App Review store (2, 2026-09-14). The 63 duplicates (66 incl. keepers) held no products/orders/conversations.
- "41 installs in August" was one shop looping in one day, not growth.
