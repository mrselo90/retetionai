## Context
- Main focus: Shopify IP allowlist requirement for public apps (email "Three days to enable IP allowlist before delisting").
- Environment: Dev Dashboard → Recete → Settings → IP allowlist; production server 167.172.60.234.

- Allowlist the production server's single IPv4 address only (167.172.60.234/32); no ASN, since an ASN would admit every DigitalOcean customer.
- The Admin API is called only from that server (shopify-app shell, plus api/workers through @recete/shared). The server has no IPv6, and its connection to Shopify uses IPv4.

## Changes
- IP allowlist: 167.172.60.234/32 added. Run test (Oct 20 – Nov 18): "0 of 467 requests would be blocked". "Enforce IP allowlist" turned on and saved; status Enabled.

## Deployments
- None (dashboard setting only).

## Observed Issues
- Shopify timeline: Nov 12 bulk operations blocked without an allowlist (we use none); Nov 20 delisting and new installs blocked; Jan 15, 2027 merchant warning; Apr 1, 2027 Admin API requests rejected.
- After the change, the server's catalog call (/api/integrations/shopify/products) returned 200; no Shopify 403s in the logs.

## Open Items

- Admin API calls with production tokens from any other machine (laptops, CI) are now rejected.
